What tang is: a differentiable computing library. Math written generic over `S: tang::Scalar` runs with `f64` for values or `tang::Dual<f64>` for exact derivatives. `tang-expr` traces the same code into a graph you can differentiate (`diff`, reverse mode with `vjp`) and compile to CUDA, Metal, WGSL or C. `tang-la` has dense linear algebra, `tang-optim` has Adam, L-BFGS and Levenberg–Marquardt, and `tang-train` has layers and a Trainer. How to proceed: 1. Read the tang README and the examples in the crates you plan to use. 2. How tang works

      
Four ideas carry the whole library. Each is small enough to state in one equation, and one example, , runs through all of them.

In tang this is just a type. Code written once over S: Scalar computes values with f64 and derivatives with Dual<f64>, with no tape and no symbolic engine. For many inputs, the same functions trace into a graph instead, and tang-expr runs reverse mode over it.

Above the scalar level, every tensor operation is one form. A comprehension maps each output index to a reduction over some inputs, each read through a view, an affine map from indices to memory:

3Optimizations are derived, not written

        
Because everything is one form, the compiler's passes are rewrites over that form. Fusion is a single rule: substitute a map into its consumer. Gradients are comprehensions too.
